# Task Tracker API

A small ASP.NET Core API for managing tasks stored in SQL Server. The API uses endpoint modules, Entity Framework Core, and has no authentication configured.

## Requirements

- .NET SDK matching the project's `net8.0` target
- SQL Server database with permission to create and modify `dbo.Task`

> **Support status:** This repository currently targets .NET 8, whose support ended on November 10, 2026. Its EF Core SQL Server and SQLite packages are still on 6.0.25. Upgrade the target framework and EF Core packages to supported, matching versions before using this as a production service.

## Run locally

The `TaskTrackerApi` launch profile sets `Environment=local` and uses `https://localhost:7213` and `http://localhost:5154`. When `Environment` is `local`, the application loads `src/appsettings.Development.json`.

Create or update that local-only file with a SQL Server connection string:

```json
{
  "SqlServerDbConnectionString": "Server=<server>;Database=<database>;User ID=<user>;Password=<password>;TrustServerCertificate=True"
}
```

Then run:

```powershell
dotnet restore TaskTrackerDotnetDemo.sln
dotnet run --project src/TaskTrackerApi.csproj
```

Swagger is enabled for local and ASP.NET Core Development environments:

- https://localhost:7213/swagger
- http://localhost:5154/swagger

The connection string can also be supplied as the `SqlServerDbConnectionString` environment variable. In non-local environments, configure it through the hosting platform's secret settings; the Development settings file is not loaded there.

## Database

Run `src/SqlServerDbDeployment.sql` against the target database to create and seed `dbo.Task`. **This is a destructive reset script:** it drops the existing table and all its data before recreating it. Do not run it against a database whose existing task data must be retained.

The table fields are:

| Field | SQL type | Notes |
| --- | --- | --- |
| `Id` | `INT IDENTITY(1,1)` | Primary key, generated by SQL Server |
| `Text` | `NVARCHAR(255)` | Required |
| `Day` | `NVARCHAR(32)` | Required; stored as a string |
| `Reminder` | `BIT` | Required |

## API

All routes are relative to the service root. Request and response bodies use JSON.

| Method | Route | Behavior | Success |
| --- | --- | --- | --- |
| `GET` | `/tasks` | List tasks ordered by Id | `200 OK` |
| `GET` | `/tasks/{id}` | Get one task | `200 OK`; `404 Not Found` if absent |
| `POST` | `/tasks` | Create a task; Id is generated by the database | `201 Created`; `400 Bad Request` for blank Text or Day |
| `PUT` | `/tasks/{id}` | Replace Text, Day, and Reminder | `200 OK`; `400` or `404` |
| `DELETE` | `/tasks/{id}` | Delete a task | `204 No Content`; `404 Not Found` if absent |

Example create request (do not include `id`):

```json
{
  "text": "Buy groceries",
  "day": "2026-11-23T12:00",
  "reminder": true
}
```

Unhandled exceptions are logged and returned as sanitized `application/problem+json` 500 responses. The create endpoint maps any `DbUpdateException` to `409 Conflict`.

## CORS and security headers

The default CORS policy allows credentialed requests from:

- `https://goldfish-app-zhi87.ondigitalocean.app`
- `http://localhost:4200`

It allows any request header and method for those origins. Update this allow-list to match the deployed frontend(s). ASP.NET Core's CORS middleware handles preflight requests.

Responses also receive `Strict-Transport-Security`, `X-Frame-Options: DENY`, and `Content-Security-Policy: frame-ancestors 'none'`. HTTPS redirection is enabled outside local and Development environments. The hosting platform should terminate and enforce HTTPS appropriately.

## Tests

Run both the SQLite-backed service unit tests and HTTP integration tests:

```powershell
dotnet test TaskTrackerDotnetDemo.sln -c Debug
```

The integration tests use `WebApplicationFactory<Program>` and replace `ITaskService` with a mock. They exercise routing, request validation, CORS preflight behavior, Swagger document generation, and error responses without requiring a live SQL Server. They do not verify connectivity to a deployed database.

## Publish and deploy

Publish a framework-dependent Release build locally:

```powershell
dotnet publish src/TaskTrackerApi.csproj -c Release -o .\publish
Compress-Archive -Path .\publish\* -DestinationPath .\publish.zip -Force
```

The `*` is important: published files, including `TaskTrackerApi.dll`, must be at the ZIP root, not nested under a `publish` directory. Deploy the ZIP with Azure CLI, substituting your resource group and app name:

```powershell
az webapp deploy `
  --resource-group <resource-group> `
  --name <app-service-name> `
  --src-path .\publish.zip `
  --type zip
```

Configure `Environment=Production`, `ASPNETCORE_ENVIRONMENT=Production`, and `SqlServerDbConnectionString` in App Service settings. Keep the App Service portal CORS list as `*` when using the application's CORS middleware, so only one layer handles CORS. `/swagger` is not enabled in Production; `/version` reports the running assembly version and file timestamp for deployment checks.

## Repository security before first push

Do not commit credentials. Before initializing or pushing this repository, remove and rotate any credentials currently present in `setup.sh` and `src/appsettings.Development.json`. Store local or deployed connection strings outside source control (for example, in a local secret store or App Service application settings). Verify the ignore rules match the exact case of `appsettings.Development.json` on case-sensitive filesystems.
